# ESP32-S3 WiFi Print Server (LPT / Centronics) — универсальный

Порт проекта [gianluca-nitti/printserver-esp8266](https://github.com/gianluca-nitti/printserver-esp8266) на **ESP32-S3-DevKitC-1 N16R8** с расширенным функционалом: прямое управление LPT без сдвигового регистра, все статусные линии принтера, OLED-индикация, печать с Android и ПК по сети. Прошивка **не привязана к модели принтера** — работает с любым Centronics-принтером, понимающим PCL.

Прошивка собирается **PlatformIO** (уже собрана, см. `firmware/`) и **Arduino IDE 2** (скетч `printserver.ino`; см. раздел «Сборка» — важное про пустой .ino).

---

## Возможности

| Функция | Статус |
|---|---|
| Прямой LPT без сдвигового регистра (8 данных + STROBE + BUSY/ACK/PE/SELECT/ERROR/INIT/SELECTIN/AUTOFD) | ✅ |
| Корректный хендшейк Centronics (setup/hold STROBE, ожидание цикла BUSY) — фикс «странностей» печати | ✅ |
| OLED 0.91" 128×32, обе строки крупным шрифтом 6×12 с кириллицей | ✅ |
| WiFi STA + точка доступа с веб-настройкой: **сканирование сетей списком + ручной ввод** (urlDecode `+`/`%XX` — фиксы PR #1/#2 включены) | ✅ |
| Очередь печати на LittleFS с монотонными ID (фикс зацикливания после 255 заданий) | ✅ |
| Raw 9100 (JetDirect/AppSocket) | ✅ |
| IPP 1.1: Get-Printer-Attributes / Validate-Job / Print-Job; Content-Length **и** chunked; Expect: 100-Continue | ✅ |
| **PWG-raster → PCL**: Android рендерит PDF в `image/pwg-raster`, прошивка декодирует (sync RaS2, заголовок 1796 Б, PackBits) и конвертирует в PCL-растр — проверено хост-тестом (`tests/test_pwg.cpp`, запуск `tests/run_tests.sh`) | ✅ |
| mDNS/Bonjour: `_ipp._tcp` + TXT `rp=lp` (обнаружение Android), `_pdl-datastream._tcp`, `_http._tcp` | ✅ |
| Веб-панель состояния и настройки WiFi на http://<ip>/ | ✅ |
| LPD (порт 515, RFC 1179) | ⏸ не начат |

## Подключение (DB25 принтера → ESP32-S3)

**Важно:** ESP32-S3 — устройство 3.3 В. Выходы ESP32 на линии данных/STROBE/INIT/SELECTIN/AUTOFD читаются принтером (5В TTL) как валидные уровни напрямую. Обратные линии принтера (5 В) **обязательно** делить резисторами: 10 кОм (со стороны принтера) + 20 кОм (на GND) дают ~3.3 В на входе GPIO.

| DB25 (принтер) | Сигнал | Направление | GPIO ESP32-S3 | Примечание |
|---|---|---|---|---|
| 2–9 | D0–D7 | ESP32 → принтер | 4, 5, 6, 7, 10, 11, 12, 13 | напрямую |
| 1 | /STROBE | ESP32 → принтер | 14 | напрямую |
| 10 | /ACK | принтер → ESP32 | 15 | делитель 10к/20к |
| 11 | BUSY | принтер → ESP32 | 21 | делитель 10к/20к |
| 12 | PAPER END | принтер → ESP32 | 16 | делитель 10к/20к |
| 13 | SELECT | принтер → ESP32 | 17 | делитель 10к/20к |
| 15 | /ERROR | принтер → ESP32 | 18 | делитель 10к/20к |
| 16 | /INIT | ESP32 → принтер | 38 | напрямую |
| 17 | /SELECT IN | ESP32 → принтер | 39 | напрямую, держать LOW |
| 14 | /AUTO FEED | ESP32 → принтер | 40 | напрямую, держать HIGH |
| 18–25 | GND | общий | GND | обязательно все, параллельно |
| — | OLED SDA/SCL | | 8 / 9 | I2C 0x3C |
| — | кнопка BOOT | | 0 | уже на плате DevKitC-1; удержание 3 с = AP |
| — | RGB LED | | 48 | уже на плате (WS2812); опционально простой LED на GPIO2 |

Пины выбраны так, чтобы не задеть: strapping (0, 3, 45, 46), SPI-флеш (26–32), PSRAM octal (33–37), USB (19/20).

## Сборка и прошивка

### PlatformIO (рекомендуется)

```bash
pip install platformio
pio run                    # сборка
pio run -t upload          # прошивка (USB-C DevKitC-1)
pio device monitor         # лог 115200
```

### Arduino IDE 2

Установить поддержку «esp32 by Espressif Systems»; плата **ESP32S3 Dev Module**, Flash Size 16MB, PSRAM: OPI PSRAM, USB CDC On Boot: Enabled. Открыть `printserver.ino` и собрать.

**Про структуру:** раскладка плоская, как в оригинальном проекте — все `.cpp/.h` лежат рядом с `printserver.ino`, а `setup()`/`loop()` находятся в самом `.ino`. Arduino IDE и PlatformIO (конфиг `platformio.ini` с `src_dir = .`) собирают всё одинаково; отдельного `main.cpp` нет.

Готовые артефакты в `firmware/`: `firmware.bin`, `bootloader.bin`, `partitions.bin` (загрузка: `esptool.py --chip esp32s3 write_flash 0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin`).

## Использование

1. Первый запуск: OLED «подключение к wifi...» → «AP 192.168.4.1». Подключитесь к сети `ESPPrintServer-XXXX`, откройте http://192.168.4.1/wifi — страница покажет **список найденных сетей** (сигнал, открытая/закрытая); клик по сети подставит её SSID, останется ввести пароль. Сети отсортированы по алфавиту. Можно и ввести SSID вручную (кнопки «Ручной ввод» внизу). Пробелы и спецсимволы в пароле поддерживаются.
2. После подключения OLED: «IP 192.168.x.x», вторая строка — `ESPPrint-XXXX.local` (длинное имя прокручивается). Если принтер не подключён по LPT, на второй строке «принтер не подключен» (после подключения принтера — «готов»).
3. **Windows:** любой PCL-драйвер (например «HP Universal Printing PCL» или Generic / Text Only) → порт Standard TCP/IP, **RAW 9100**. Или IPP: `http://IP:631/lp`.
4. **Linux/macOS CUPS:** `lpadmin -p LPT -E -v socket://IP:9100 -m drv:///generic/generic.ppd` (для PCL-принтера — его PPD), или `ipp://IP/lp`.
5. **Android — печать без приложений (системная служба):**
   - Телефон и принт-сервер в одной WiFi-сети.
   - Система: Настройки → Подключённые устройства → Подключения → Печать (или «Печать по умолчанию», зависит от версии Android) → **Системная служба печати**.
   - Принтер `ESP LPT PrintServer` появится в списке **автоматически** через несколько секунд (mDNS `_ipp._tcp`). Нажмите на него — скачаются «возможности» (Get-Printer-Attributes).
   - Если принтер не появился автоматически: в той же службе есть «Поиск принтеров в Wi-Fi сети» / «Все принтеры» → он должен быть там. **Ввод IP вручную** (`192.168.1.45`) во многих прошивках Android работает только для IPP-принтеров с полным профилем; если вручную пишется «принтер не поддерживается» — это нормально для урезанного клиента: используйте автопоиск по mDNS (основной путь) или обновите прошивку принт-сервера до этой версии, где `document-format-supported` содержит `image/pwg-raster` (раньше Android его не находил и отклонял принтер).
   - Печать: «Поделиться» → Печать, или из приложения. Android сам отрендерит документ в PWG-raster (300 dpi, ч/б), прошивка сконвертирует в PCL и выведет на LPT.
   - Веб-панель http://IP/ покажет состояние и очередь.
6. Индикация: «Загрузка данных» → «печать...»; «нет бумаги»/«ошибка» — задание ждёт в очереди, продолжится после устранения проблемы.

## Индикация светодиодом и кнопка

Состояние дублируется встроенным RGB-светодиодом DevKitC-1 (GPIO48, `PIN_LED_RGB` в `config.h`) — на случай, если OLED не работает или не установлен. Если платы без WS2812 — можно повесить простой светодиод на GPIO2 (`PIN_LED_WIFI`, анод через резистор ~470 Ом), он мигает те же паттерны. «255» в `config.h` = элемент не используется.

| Цвет | Режим | Что означает |
|---|---|---|
| синий | мигание 2 Гц | подключение к WiFi («Подкл. к ХХХ» на OLED) |
| зелёный | горит | подключено к WiFi |
| жёлтый | мигание 1 Гц | режим точки доступа (настройка; после удержания кнопки — «настройка», иначе «сеть не найдена») |
| голубой | мигание 5 Гц | приём задания |
| малиновый | мигание 5 Гц | печать |
| красный | мигание 4 Гц | принтер требует внимания: нет бумаги / ошибка (печать остановлена, задание в очереди) |

**Кнопка BOOT** (GPIO0, `PIN_BTN`): удержание ~3 с (`BTN_HOLD_MS`) в любой момент — включая время, когда прошивка «зависла» в подключении к плохой сети, — принудительно разрывает WiFi и открывает точку доступа `ESPPrintServer-XXXX` для переконфигурации. На OLED «настройка» вместо «сеть не найдена». Фоновые попытки вернуться на старую сеть выключены, пока не будут сохранены новые креденшлы через веб-панель (или не появится сохранённая сеть — при обычном, некнопочном AP-режиме ретраи каждые 2 минуты остаются).

## Исправленные ошибки оригинала

1. **Хендшейк LPT** (`ParallelPort.cpp`): в оригинале данные выставлялись и STROBE дёргался без времени установки, и после STROBE не ждался цикл BUSY — на быстром ESP32-S3 это теряло байты (пропуски строк, битые символы). Теперь: setup ≥1 мкс, импульс STROBE 2 мкс, ожидание цикла BUSY с таймаутом.
2. **Очередь** (`PrintQueue.cpp`): `byte head/tail` переполнялись после 255 заданий. Теперь 32-битные монотонные ID + каталог `/q/` + чистка мусора при загрузке.
3. **WiFi-креды** (PR #1/#2): urlDecode и `WiFi.persistent(true)` — интегрированы.
4. **Блокирующие чтения**: вместо `waitAvailable()` с `delay(10)` — асинхронный pump.
5. **IPP**: атрибуты multi-value теперь корректны (имя только у первого значения, остальные с name-length 0), `printer-state` — настоящий enum, `printer-is-accepting-jobs` — boolean; добавлены `pwg-raster-document-*`, поддержка chunked и Expect: 100-Continue.

## Известные ограничения / TODO

- LPD-сервер (515) не начат.
- Конвертер PWG→PCL: порог светлоты фиксирован (gray<128 → чёрный), бумага всегда A4 в PCL-заголовке (содержимое растра не масштабируется) — при печати Letter край может обрезаться; при желании доделайте по `PageSize` из заголовка.
- AirPrint (iOS) требует `_ipp._tcp` + `_universal._sub._ipp._tcp` и полного IPP-профиля — пока не заявлено.
- Хост-тест декодера: `tests/run_tests.sh` (вручную: `cd tests && g++ -std=c++17 -I. -Iarduino_shim -o test_pwg test_pwg.cpp && ./test_pwg`).

## Структура

```

```
